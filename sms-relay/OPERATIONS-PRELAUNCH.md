## Monitoring implementation (not deployed)

After separate deployment approval and schema migration, an operator can run as the app owner:

```sh
p=/home/master/applications/hecshantfz/private_html/ieb-relay
IEB_RELAY_CONFIG="$p/config.json" /usr/bin/php "$p/code/ops-monitor.php"
```

Install outside the public web root with restrictive app-owner permissions. The script emits counts only. Exit 0 = no alerts, 2 = one or more alerts, 1 = monitor unavailable. Alerts include unknown and expired-unknown alerts, unknown verification sends, old due work and expired queue backlog, and failed/expired/capped alerts. This is a **snapshot, not an alert service, or proof the scheduler ran**. Counts for terminal states persist and require a separately designed acknowledgment/delta strategy. Verification cleanup changes old `unknown` states to `expired`; if no observer captures the count before cleanup, uncertainty can disappear from this snapshot. Unknown sends are never automatically retried. Add an independently monitored heartbeat/alert channel and verify it fails when cron stops; assign a real owner and response SLA before activation. Investigate counts in secured tools without exporting PII. Do not automatically retry unknowns or manually reset them to queued.

**Delivery visibility, not a guarantee:** newly accepted lead alerts store the Twilio SID in the private SQLite database and are reconciled by bounded, authenticated SDK GET lookups (not a public status callback). `accepted` and `sent` are not delivered; `delivered`, `undelivered`, `failed`, and `canceled` are separate terminal statuses. No status callbacks are configured or required. Lookups run only if `status_poll_enabled` is explicitly true; they never send. Each pass selects at most 20 due records, at five-minute intervals, stops automatically after 24 hours, and leaves stale records for investigation. Lookup errors, stale nonterminal messages, failures, overdue polling and old accepted rows with no SID are reported by the aggregate monitor. This is a snapshot requiring an independently monitored owner and heartbeat, not automatic escalation. Legacy accepted messages and verification-code sends lack SIDs; a timeout or crash can mean a message went out with no SID. Never blindly resend unknowns or restore old queue states. This is fake-tested locally only, not proof of carrier delivery.
